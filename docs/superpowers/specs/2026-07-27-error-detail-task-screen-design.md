# Отдельная страница ошибки

## Решение

Центр ошибок остаётся списком с показателями и фильтрами. Нажатие на строку больше не раскрывает подробности под списком: приложение переходит на адрес `/admin/server/errors/<id>` и открывает полноэкранный `TaskScreen` поверх основного интерфейса.

## Страница инцидента

- Стандартная верхняя панель приложения содержит кнопку «Назад», заголовок «Ошибка» и название инцидента.
- В начале страницы показываются статус, важность, источник, раздел, версия, количество событий, клиентов и устройств.
- Основные действия «В работу», «Решено» и «Игнорировать» находятся до технических данных и имеют зоны нажатия не меньше 44 px.
- Ниже располагаются копирование полного отчёта, технический тип, события со стеком и статусы доставки push/email.
- После изменения статуса страница остаётся открытой и сразу показывает новое состояние.

## Навигация

- Новая task-route: `/admin/server/errors/:errorId`.
- Возврат ведёт к `/admin/server/logs` и сохраняет центр ошибок как список.
- Push и email ведут сразу на новую страницу конкретного инцидента.
- Старые ссылки `/admin/server/logs?error=<id>` продолжают открывать полноэкранную страницу и не ломаются.
- Тестовый инцидент после создания открывается тем же способом.

## Компоненты

- `AdminSection.vue` распознаёт новый маршрут как серверный раздел.
- `AdminServerPanel.vue` связывает текущий маршрут с `AdminErrorTracker` и отвечает за переходы.
- `AdminErrorTracker.vue` отделяет список от detail task-screen через входной `errorId` и события `open-error`/`close-error`.
- API и схема данных не меняются; меняются только ссылки уведомлений.

## Проверка

- Компонентные тесты фиксируют отсутствие inline-карточки, открытие через событие и полноэкранный TaskScreen по `errorId`.
- Тесты навигации проверяют новый маршрут, старую query-ссылку, закрытие и прямой переход из уведомления.
- Визуальная проверка проводится на 320, 390, 768, 1024 и 1440 px.
- Перед выпуском выполняются полные проверки типов, тестов, сборки и production health/readiness.

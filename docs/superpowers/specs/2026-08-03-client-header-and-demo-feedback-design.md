# Компактная карточка клиента и обратная связь демо-аналитики

## Цель

Убрать повторяющиеся персональные данные с первого экрана карточки клиента и сделать повторную генерацию демо-аналитики очевидной. В финансовом отчёте должны отображаться все настроенные продукты как отдельные записи по их ID, без служебных плашек типа оплаты.

## Карточка клиента

- Стандартная шапка задачи получает необязательный слот содержимого; все существующие экраны сохраняют текущие `title` и `subtitle`.
- Только карточка клиента использует слот: аватар, имя, строка «Последний вход» и метки доступа, срока и тарифа.
- Почта и роль не выводятся в шапке.
- Отдельная повторная карточка личности удаляется.
- Блок «Контактные данные» остаётся на прежнем месте со всей логикой почты, телефона, копирования и ограничения владельцем.
- Корзина владельца остаётся отдельной кнопкой шапки с областью нажатия 44×44 px.

## Демо-аналитика

- Нажатие «Сгенерировать» сразу меняет seed, запускает короткую анимацию и временно показывает текст «Данные обновлены» через `aria-live`.
- Повторное нажатие корректно перезапускает состояние обратной связи.
- Финансовый список строится по уникальным ID всех продуктов, полученных из `/admin/stats`; одинаковые названия не объединяются.
- Плашки «Разовая оплата» и «Автоподписка» в строках продуктов удаляются. Название, выручка, оплаты, клиенты и средний чек остаются.
- Для удержания каждому платившему демо-клиенту назначается последний продукт и последняя платёжная система. Активные и ушедшие считаются внутри этих взаимоисключающих групп, поэтому суммы совпадают с общей сводкой, а проценты не обнуляются ошибочно.
- Блоки «Отток по последнему продукту» и «Отток по платёжной системе» оформляются компактными адаптивными карточками с названием, процентом, строкой `X из Y не продлили` и короткой шкалой.

## Проверка

- Компонентный тест карточки клиента проверяет единичное отображение имени, последний вход и статусы в шапке, отсутствие почты в шапке и сохранность блока контактов.
- Компонентный тест финансов проверяет несколько одноимённых продуктов с разными ID и отсутствие служебных плашек.
- Тест навигации аналитики проверяет состояние подтверждения после нажатия генерации.
- Тест генератора проверяет ненулевой реалистичный отток и точное совпадение сумм breakdown со сводкой удержания.
- Проверяются TypeScript, unit-тесты, production build и release E2E на мобильных и десктопных viewport.

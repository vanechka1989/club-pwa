# Центр результатов ДЗ

## Цель

Заменить крупное одиночное сообщение в блоке прогресса на компактную кнопку «Проверки ДЗ» со счётчиком. По нажатию открывается отдельный полноэкранный task-screen «Результаты ДЗ» со всеми актуальными проверками пользователя.

## Поведение

- Кнопка показывается, когда есть хотя бы один незакрытый результат проверки.
- Счётчик показывает число результатов; значения больше 9 отображаются как `9+`.
- Экран открывается одинаково при одном и нескольких результатах.
- Каждая запись показывает состояние «Домашнее задание не принято» или «ДЗ принято», урок, отдельную подпись «Комментарий модератора», текст комментария, дату проверки и действие открытия урока.
- У каждой записи есть собственная кнопка-крестик с доступным названием. Нажатие сразу убирает только эту запись.
- Закрытие хранится на сервере для аккаунта. Перезапуск PWA и другое устройство не возвращают закрытую запись.
- Новая версия сдачи и её новая проверка создают новую запись, даже если предыдущая проверка была закрыта.
- Если закрыта последняя запись, экран показывает спокойное пустое состояние, а после возврата кнопка в блоке прогресса исчезает.

## Данные и API

Вместо `latestHomeworkReview` ответ `GET /learning` содержит массив `homeworkReviewNotices`. Элемент включает `submissionId`, `contentItemId`, статус, комментарий и время проверки. Сервер выбирает последние версии проверенных сдач и исключает записи, закрытые текущим пользователем.

Таблица `homework_review_dismissals` хранит пары `user_id + homework_submission_id` с уникальным ограничением. `POST /learning/homework-reviews/:submissionId/dismiss` проверяет принадлежность сдачи текущему пользователю и идемпотентно создаёт запись закрытия.

## Интерфейс

`LearningProgressHero` получает только количество результатов и событие открытия центра. Список вынесен в отдельный `HomeworkReviewResultsTask.vue`, использующий общий `TaskScreen`. Карточки не вложены в другие карточки, крестик имеет зону нажатия 44×44 px, длинные комментарии переносятся без горизонтальной прокрутки.

## Ошибки и проверки

При неудаче закрытия запись возвращается в список и показывается понятная ошибка. Проверяются контракт схемы, сериализация и фильтрация закрытий, авторизация endpoint, независимое закрытие двух записей, переход в урок, пустое состояние, ширины 320/390/768/1024/1440 и обе цветовые схемы проекта.

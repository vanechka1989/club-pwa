# Компактные переключатели и тестовый инцидент

## Цель

Исправить чрезмерный размер галочек каналов уведомлений и дать владельцу понятный способ проверить весь путь трекера ошибок.

## Интерфейс

- Каналы `PWA push` и `Email` отображаются как две компактные строки с нативным checkbox размером 20×20 px.
- Вся строка сохраняет мобильную область нажатия не менее 44 px.
- Рядом с обновлением центра ошибок появляется вторичная кнопка `Создать тестовую ошибку`.
- Во время запроса кнопка блокируется. После успеха список и счётчики обновляются, тестовая карточка открывается, а интерфейс сообщает, что уведомления отправлены по включённым каналам.

## Серверный сценарий

- Новый owner-only endpoint создаёт один критический инцидент с заголовком `[ТЕСТ] Проверка центра ошибок`.
- Инцидент проходит обычные группировку, хранение и отправку PWA push/email; отдельного обходного канала нет.
- Событие связывается с владельцем, содержит маршрут `/admin/server/logs` и безопасные тестовые данные без персональной информации.
- Административное действие записывается в журнал.

## Проверка

- Компонентный тест проверяет доступность компактных переключателей и создание/открытие тестового инцидента.
- API-тест проверяет формирование тестового события и немедленное уведомление как для критической ошибки.
- После deployment один тестовый инцидент создаётся через интерфейс владельца; реальные оплаты не затрагиваются.

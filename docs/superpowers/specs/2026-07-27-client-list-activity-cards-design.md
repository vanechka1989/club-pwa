# Карточки клиентов с акцентом на активность

Дата: 27 июля 2026 года.

## Цель

Сделать список клиентов визуально выразительным и удобным для быстрого просмотра, не меняя бизнес-логику раздела. Главным показателем карточки становится дата последнего входа. Клиенты всегда отображаются от самого недавнего входа к более раннему.

## Область изменений

Изменяется список клиентов в административном разделе, локальная подготовка данных и существующий контракт `AdminStatsUser.lastLoginAt`: поле становится nullable, а API возвращает `null`, если у клиента нет auth-сессии. Новых endpoint и полей не добавляется, схема базы данных сохраняется.

## Визуальная структура карточки

Карточка остаётся одной большой кнопкой с минимальной областью нажатия 44 × 44 px и состоит из четырёх смысловых зон:

1. Аватар или инициалы клиента.
2. Имя и основной контакт: email, а при его отсутствии username.
3. Вторичная информация: понятное название тарифа и прогресс обучения.
4. Акцентный блок справа: дата последнего входа и статус доступа.

По левому краю карточки размещается тонкая статусная полоса:

- зелёная — доступ открыт;
- жёлтая — клиент ограничен;
- красная — доступ закрыт.

Статус дополнительно подписывается компактной плашкой и не передаётся только цветом. Дата последнего входа получает более высокий визуальный контраст, чем тариф и прогресс, но не конкурирует с именем клиента. Стрелка перехода остаётся видимой.

## Сортировка

После применения существующего поиска и фильтров результат сортируется по `lastLoginAt` в убывающем порядке:

- самый свежий вход находится сверху;
- более ранние входы следуют ниже;
- клиенты без сохранённого входа находятся в конце;
- при одинаковом времени входа порядок стабилизируется по отображаемому имени, затем по идентификатору клиента.

Отдельный переключатель сортировки не добавляется. На экране можно оставить неброскую подпись «Последний вход ↓», поясняющую текущий порядок без дополнительного управления.

Для отсутствующей даты карточка показывает «Не входил» вместо некорректной или пустой даты.

## Адаптивность и темы

Карточки проектируются от ширины 320 px. На узких экранах имя и контакт сокращаются многоточием, вторичные показатели могут переноситься внутри центральной зоны, но дата последнего входа и статус остаются видимыми. Горизонтальная прокрутка не допускается.

Все цвета строятся на существующих семантических переменных приложения. Решение должно одинаково работать во всех пяти текущих темах в светлом и тёмном режимах, сохранять контраст WCAG AA и контраст индикатора клавиатурного фокуса не ниже 3:1.

## Компоненты и данные

- `AdminSection.vue` продолжает владеть фильтрами и передаёт готовый список в панель клиентов.
- Shared schema описывает `lastLoginAt` как `string | null`; API берёт значение только из последней auth-сессии и не подставляет `createdAt`.
- Чистая функция подготовки списка фильтрует клиентов и возвращает новую отсортированную коллекцию, не изменяя исходной коллекции API.
- `AdminClientsPanel.vue` отвечает только за представление карточки и события выбора клиента.
- Существующие функции статуса доступа, тарифа, форматирования дат и заголовка клиента переиспользуются.

Новых запросов к серверу, полей API и миграций базы данных не требуется; меняется только nullability существующего поля.

## Состояния

- Загрузка и ошибка получения списка сохраняют текущее поведение раздела.
- Пустой результат после фильтров сохраняет существующее пустое состояние.
- Клиент без фото получает инициалы.
- Клиент без email показывает username; при отсутствии обоих дополнительная контактная строка не выводится.
- Клиент без `lastLoginAt` получает текст «Не входил» и находится в конце списка.

## Проверка

Автоматические тесты должны подтвердить:

- сортировку по `lastLoginAt` от свежего к старому;
- размещение клиентов без входов в конце;
- стабильный порядок при одинаковых датах;
- совместную работу сортировки с поиском и всеми существующими фильтрами;
- отображение имени, контакта, тарифа, прогресса, последнего входа и подписанного статуса;
- сохранение доступной кнопки-карточки и существующего перехода к клиенту.

Визуальная проверка выполняется на ширинах 320, 390, 768 и 1024 px во всех поддерживаемых темах. Проверяются длинные имена, отсутствие контакта, каждый статус доступа, видимый фокус и отсутствие горизонтального переполнения.

Перед выпуском запускаются проверки типов, полный набор тестов, production-сборка и релизные браузерные сценарии.

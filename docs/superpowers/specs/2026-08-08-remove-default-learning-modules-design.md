# Удаление дефолтных модулей обучения

## Цель

В разделе «Модули» должны отображаться только модули, созданные человеком. Два исторических демонстрационных модуля и их уроки нужно удалить из существующей рабочей базы и не возвращать в интерфейс.

## Точный состав удаления

Служебные модули определяются только по неизменяемым seed-slug:

- `module-1-seed`;
- `module-2-seed`.

Названия, описания, состояние публикации и даты не используются для определения цели. Поэтому пользовательский модуль не будет удалён, даже если человек назвал его «Модуль 1» или «Модуль 2».

## Реализация

Добавляется отдельная идемпотентная миграция базы данных. Она удаляет категории с двумя указанными slug. Связанные демонстрационные уроки удаляются штатным каскадом внешнего ключа `content_items.category_id`.

Историческая миграция `0017_delete_legacy_learning_content.sql` не изменяется: уже применённые миграции остаются неизменными, а новая очистка выполняется на всех средах одинаково.

Клиентская логика не получает фильтр по названию или описанию. После миграции API возвращает только реально оставшиеся модули. Тестовые фикстуры сохраняются исключительно для изолированных автоматических тестов и не участвуют в рабочем приложении.

## Безопасность данных

- Не удалять все модули массово.
- Не удалять записи по заголовку или описанию.
- Не затрагивать созданные человеком, архивные и черновые модули.
- Повторный запуск миграции безопасен и не меняет данные после первой очистки.

## Проверка

- Автоматический тест подтверждает наличие новой миграции в журнале.
- Тест миграции проверяет удаление только двух точных slug и отсутствие широкого условия удаления.
- Проверяются типы, серверные тесты и production-сборка.
- После выкладки проверяются успешное применение миграции, готовность API и версия сервера.

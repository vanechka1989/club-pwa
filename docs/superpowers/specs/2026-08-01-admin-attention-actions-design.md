# Кликабельные предупреждения аналитики — дизайн

## Цель

Сделать блок «Требуют внимания» понятным и полезным: администратор должен видеть отдельные причины и одним нажатием переходить к соответствующим записям.

## Интерфейс

Вместо одной некликабельной строки выводится компактный блок из двух независимых кнопок. Кнопки появляются только при ненулевом показателе:

- «Истекает доступ» — число клиентов и подпись «в ближайшие 7 дней»; переход сразу в существующий список клиентов `expiring_soon`.
- «Проблемы с оплатой» — число уникальных операций и подпись «за выбранный период»; переход в объединённый список проблемных платежей.

Каждая кнопка имеет предупреждающую иконку, стрелку перехода, минимум 44 px по высоте, видимый focus-state и корректную компоновку от 320 px. На узком экране элементы располагаются вертикально, на широком могут занимать две колонки.

## Данные и переходы

Проблемной считается операция, у которой `status === "failed"` или получен webhook с `isValid === false`. Одна операция, удовлетворяющая обоим условиям, считается один раз.

Для объединённой детализации добавляется ключ `attention`. Прямой маршрут `/admin/statistics/payments/attention` остаётся работоспособным после перезагрузки. В списке каждая операция показывает понятную причину: «Ошибка оплаты», «Ошибка уведомления» или обе причины.

Период для платежей совпадает с выбранным периодом аналитики. Истекающие доступы всегда определяются относительно ближайших семи дней и от периода аналитики не зависят.

## Проверка

- Unit-тест подтверждает уникальный подсчёт операции с двумя проблемами.
- Unit-тест подтверждает фильтрацию объединённой детализации и прямой маршрут.
- Контрактный UI-тест подтверждает две кнопки, обработчики, доступные подписи и мобильные стили.
- Полные `check`, unit, build и release E2E проходят перед выпуском.

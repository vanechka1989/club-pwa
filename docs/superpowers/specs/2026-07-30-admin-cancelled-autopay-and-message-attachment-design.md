# Отменённое автосписание и вложение сообщения — дизайн

## Цель

В карточке клиента отдельно показывать действующий доступ и состояние рекуррентного списания, а редактор сообщения сделать устойчивым на мобильном экране.

## Подтверждённая причина

`AdminStatsUser` содержит только тариф подписки. Статус из `user_recurrent_subscriptions` в админский API не попадает, поэтому отменённое списание отображается как обычная «Автоподписка». Кнопка вложения является отдельной колонкой grid и наследует конкурирующие размеры глобальной икон-кнопки, из-за чего на телефоне растягивается и визуально ломает поле.

## Решение

- Добавить в `AdminStatsUser` поле `recurrentPaymentStatus: "active" | "cancelled" | null`.
- Для списка клиентов загружать последние состояния рекуррентных подписок одним пакетным запросом, а не отдельным запросом для каждого клиента.
- Для рекуррентного тарифа показывать «Автоподписка» при активном списании и «Автосписание отменено» при отменённом. Доступ и дата окончания остаются отдельными бейджами.
- Отменённый статус оформить предупреждающим красно-оранжевым бейджем, активный — синим.
- Поместить кнопку вложения поверх левого нижнего края textarea. Кнопка имеет фиксированный квадрат 44 × 44 px, а поле получает достаточный левый внутренний отступ.

## Проверка

Регрессионные тесты должны подтвердить контракт API, оба текста/тона рекуррентного статуса и мобильную геометрию кнопки вложения. После локальных тестов и сборки релиз проверяется в CI и на production.

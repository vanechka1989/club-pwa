# Автозаполнение тарифа из Lava

## Цель

При создании или редактировании тарифа администратор сначала выбирает платёжную систему. Если выбрана Lava, следом выбирается синхронизированный товар Lava, после чего форма автоматически заполняет доступные данные товара.

## Поведение формы

- Блок «Платёжная система» расположен первым.
- При выборе Lava сразу под выбором платёжной системы показывается список разрешённых товаров Lava.
- После выбора товара форма переносит его название, цену и тип оплаты.
- Для рекуррентного товара срок доступа определяется по периодичности Lava: месяц — 30 дней, 90 дней — 90, 180 дней — 180, год — 365.
- Если Lava не передала цену или период, соответствующее текущее значение формы сохраняется.
- Название, тип и срок остаются редактируемыми. Фиксированная цена Lava показывается как значение из каталога и не меняется в тарифе; для динамической цены поле остаётся редактируемым.
- При выборе Prodamus форма работает как раньше.
- Ручной ввод идентификаторов Lava остаётся запасным вариантом.

## Границы

Автозаполнение выполняется на клиенте из уже синхронизированного каталога. Платёжные идентификаторы по-прежнему сохраняются в привязке тарифа, а сервер продолжает проверять наличие ровно одной платёжной системы.

При создании оплаты сумма передаётся в Lava только для предложения с динамической ценой. Для фиксированного предложения Lava использует собственную цену; сервер не разрешает сохранить тариф с отличающейся суммой, чтобы оплаченная сумма и выданный доступ не расходились.

## Проверка

- Компонент выбора товара передаёт выбранную запись каталога родительской форме.
- Чистая функция корректно переносит данные Lava и не затирает отсутствующие значения.
- Запрос фиксированного предложения не содержит поле `amount`, запрос динамического предложения содержит сумму тарифа.
- В шаблоне выбор платёжной системы расположен выше остальных полей.
- Мобильные проверки выполняются на Android и iPhone, включая ширину 320 пикселей.

# Полное удаление клиента владельцем

## Цель

Добавить на основной экран карточки клиента ярко-красную кнопку с иконкой корзины. Кнопка запускает подтверждаемое необратимое удаление обычного клиента и доступна только владельцу клуба.

## Доступ и ограничения

- Кнопка видна только пользователю с реальной ролью `owner`.
- Кнопка показывается только для обычного клиента с ролью `member`.
- API независимо проверяет реальную роль инициатора через серверную настройку владельца.
- API запрещает удалять текущего владельца и любого администратора, даже если запрос отправлен вручную.
- Preview-роль не даёт права удаления.

## Интерфейс

- Кнопка располагается справа в верхней панели карточки клиента, в отмеченном пользователем месте.
- Кнопка имеет ярко-красный фон, белую иконку корзины, доступное имя `Удалить клиента` и минимальную область касания `44 × 44 px`.
- Нажатие открывает существующий `ConfirmDialog` в danger-режиме.
- Диалог показывает имя клиента, предупреждает о полном и необратимом удалении и предлагает безопасную отмену первой кнопкой.
- Подтверждение блокируется на время запроса. При успехе карточка закрывается, маршрут возвращается к списку, данные клиентов и статистика перезагружаются. При ошибке карточка остаётся открытой и показывается сообщение.

## Серверное удаление

- Новый owner-only endpoint принимает Telegram ID выбранного клиента.
- Перед изменением данных сервер находит цель и повторно проверяет, что она не владелец и не активный/зарегистрированный администратор.
- Перед транзакцией собираются ключи файлов, принадлежащих клиенту: аватар, вложения домашних заданий, сообщений сообщества, поддержки и уведомлений.
- В транзакции удаляются зависимые записи с ограничивающими внешними ключами (индивидуальные предложения и связанные оплаты/рекуррентные подписки), затем строка пользователя. Остальные персональные данные удаляются существующими каскадами; ссылки аудита с `set null` сохраняют факт административных действий без аккаунта клиента.
- После успешной транзакции связанные объекты удаляются из основного S3. Ошибка отдельного уже отсутствующего объекта не восстанавливает удалённый аккаунт и фиксируется серверным логированием.
- До удаления создаётся административный аудит с Telegram ID и отображаемым именем цели, чтобы история действия сохранилась после обнуления `targetUserId`.

## Контракт ответа

- `200`: `{ ok: true, deletedTelegramId: string }`.
- `403`: инициатор не владелец или цель является владельцем/администратором.
- `404`: клиент не найден.
- `409`: удаление не завершено из-за целостности данных; аккаунт остаётся на месте.

## Проверки

- API: отказ обычному администратору, preview-владельцу и попытке удалить владельца/администратора; успешное удаление клиента и зависимостей; повторный запрос возвращает `404`.
- Web: корзина видна только владельцу для `member`, ярко-красная, имеет доступное имя, открывает danger-confirmation, отмена безопасна, подтверждение вызывает endpoint, блокирует повторное нажатие и закрывает карточку только после успеха.
- Адаптивность: размеры 320, 390, 768 и 1024 px, отсутствие горизонтального переполнения, область касания не меньше 44 px.
- Регрессия: focused tests, полный `pnpm check`, `pnpm test`, `pnpm build`, release E2E.

## Выпуск

Изменение выходит отдельной версией с новой записью истории обновлений и новой ревизией service worker. После deployment проверяются CI, public health/ready, публичная версия, service worker, точный server HEAD/deployed marker, контейнеры, логи и создание owner-уведомления о релизе.

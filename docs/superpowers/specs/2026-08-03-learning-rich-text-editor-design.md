# Форматированный редактор текста в уроках

## Цель

Заменить обычные многострочные поля в редакторе урока единым безопасным редактором форматированного текста. Редактор используется в основном поле «Содержимое урока» и в поле «Текст / заметка» каждого дополнительного материала. Основной сценарий должен быть удобен на телефоне, а ручное редактирование HTML остаётся доступным как дополнительный режим.

## Пользовательский сценарий

Автор открывает создание или редактирование карточки урока и вводит текст в визуальном режиме. Он может применить жирное, курсивное и подчёркнутое начертание, создать список или добавить ссылку. Дополнительные команды форматирования и режим исходного HTML доступны из компактного меню. После сохранения участник видит отформатированный текст в основном содержимом урока и в дополнительных материалах.

Существующие уроки с обычным текстом продолжают открываться, редактироваться и отображаться без потери текста и переносов строк.

## Компоненты и поток данных

- Создать переиспользуемый Vue-компонент форматированного редактора с `v-model`, визуальным режимом и режимом HTML.
- Использовать один экземпляр для `lessonContent` и отдельный экземпляр для `material.body` каждой дополнительной карточки.
- Переиспользовать допустимый набор HTML из рассылок: абзацы, переносы, заголовки второго и третьего уровня, жирный, курсив, подчёркивание, цитаты, код, упорядоченные и неупорядоченные списки и ссылки.
- Нормализовать старый обычный текст в безопасный HTML при показе и редактировании, сохраняя переносы строк.
- Сохранять подготовленный HTML в существующих полях `body`; миграция базы данных не требуется.
- Отображать содержимое урока и заметки материалов как очищенный HTML вместо интерполяции обычного текста.

Компонент отвечает только за ввод и переключение режимов. Нормализация и очистка HTML оформляются отдельными функциями, чтобы использовать их при редактировании, отображении и подготовке API-запросов.

## Мобильный интерфейс

- Визуальный режим открыт по умолчанию; HTML не занимает место в основном сценарии.
- Сенсорные цели имеют размер не меньше 44 × 44 px.
- Жирный, курсив, список и ссылка доступны непосредственно на компактной панели; редкие команды и HTML открываются через дополнительное меню.
- Панель не создаёт горизонтальную прокрутку и остаётся доступной при прокрутке поля.
- Выделение текста сохраняется при нажатии команд форматирования.
- Ссылка вводится через адаптированный диалог приложения, а не через системный `prompt`.
- Экранная клавиатура не перекрывает активную область и действия сохранения.
- Интерфейс проверяется на ширинах 320, 390 и 768 px, а также в портретной и горизонтальной ориентации телефона.

На планшете и компьютере панель может показывать все команды сразу, не меняя модель данных или поведение редактора.

## Безопасность и совместимость

HTML очищается дважды: перед отображением в браузере и при записи через API. Скрипты, стили, обработчики событий, изображения, встраиваемые элементы и неизвестные теги удаляются. Ссылки разрешают только безопасные внутренние пути и протоколы HTTP, HTTPS и `mailto`; внешние ссылки получают безопасные атрибуты открытия.

API остаётся совместимым с текущими клиентами и принимает строки в существующих полях. Старый обычный текст не считается доверенным HTML и проходит ту же нормализацию. Ограничения длины применяются к сохранённому содержимому после очистки и возвращают существующий формат ошибки валидации.

## Ошибки и состояния

- Пустой редактор сохраняется как пустая строка или `null` согласно текущему контракту поля.
- Если после очистки введён только запрещённый HTML, поле считается пустым.
- Некорректная ссылка не добавляется; редактор показывает понятное сообщение и сохраняет введённый текст.
- При ошибке сохранения содержимое редактора остаётся на экране и может быть отправлено повторно.
- Переключение между визуальным и HTML-режимом не должно терять выделение, текст или допустимое форматирование.

## Проверка

- Модульные тесты нормализации проверяют обычный текст, переносы, допустимые теги, небезопасные теги и ссылки.
- Тесты компонента проверяют ввод, форматирование, переключение режимов и обновление `v-model`.
- Тесты `LearningSection` подтверждают применение редактора к основному тексту и всем дополнительным заметкам, а также форматированный вывод участнику.
- API-тесты подтверждают серверную очистку основного `body` и `materials[].body`.
- Мобильная проверка подтверждает отсутствие горизонтального переполнения, доступность кнопок, поведение клавиатуры и сохранение выделения.
- Полный набор затронутых web- и API-тестов и production-сборка должны пройти без новых предупреждений.

## Вне объёма

- Загрузка изображений непосредственно внутрь текста.
- Таблицы, изменение цвета, размера или шрифта.
- Совместное редактирование и история версий текста.
- Изменение схемы базы данных или контрактов медиафайлов.
- Обязательная замена редактора рассылок в рамках этой задачи; общий компонент должен позволить выполнить такую замену отдельно.

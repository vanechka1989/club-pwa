# Копирование отчёта и оформление уведомлений об ошибках

## Цель

Сделать диагностические данные из центра ошибок удобными для передачи разработчику, а push- и email-уведомления — понятными, фирменными и пригодными для быстрого перехода к инциденту.

## Карточка ошибки

- В заголовке раскрытой карточки появится основное действие «Скопировать отчёт» с зоной нажатия не меньше 44×44 px.
- Отчёт копируется одним текстовым блоком и содержит: заголовок, важность, статус, источник, страницу, версии, время первого и последнего события, число событий, затронутых клиентов и устройств, технический тип, сообщение последнего события, платформу, диагностический идентификатор и стек, если он есть.
- У технического идентификатора будет отдельная компактная кнопка копирования.
- После успешного копирования интерфейс показывает короткое подтверждение. При недоступном Clipboard API используется безопасный запасной способ через временное текстовое поле.
- Перед копированием значения проходят существующую очистку чувствительных данных; пароли, токены, API-ключи, подписи и email-адреса не должны попадать в передаваемый отчёт.

## Push

- Заголовок начинается с понятной отметки важности и содержит название инцидента.
- Текст показывает раздел, версию и количество повторов в пределах ограничений системного уведомления.
- Нажатие открывает конкретную карточку через `/admin/server/logs?error=<id>`.
- Push остаётся компактным: подробная диагностика доступна после перехода, а не перегружает системное уведомление.

## Email

- HTML-письмо получает адаптивную одноколоночную разметку в фирменных цветах Club PWA.
- Верхний блок показывает важность и название; ниже идут компактные показатели инцидента, раздел/версия/время и безопасный технический блок.
- Основное действие — крупная кнопка «Открыть ошибку»; рядом в обычном тексте остаётся полный URL для почтовых клиентов, блокирующих кнопки.
- В письме отсутствуют скрипты, внешние шрифты и сложная CSS-разметка; используются совместимые inline-стили и экранирование всех данных.
- Текстовая версия письма сохраняет ту же структуру и остаётся полноценной.

## Безопасность и совместимость

- Общая функция формирует безопасный диагностический отчёт для интерфейса и уведомлений, чтобы поля и правила очистки не расходились.
- Пользовательские строки экранируются для HTML, а секретоподобные фрагменты маскируются.
- Контракты API и схема базы данных не меняются.
- Доставка push/email и объединение повторов сохраняют текущую логику.

## Проверка

- Модульные тесты сначала фиксируют ожидаемый формат отчёта, очистку секретов, HTML-письмо и payload push.
- Компонентный тест проверяет обе кнопки копирования, содержимое буфера и подтверждение.
- Визуальная проверка раскрытой карточки проводится на 320, 390, 768, 1024 и 1440 px без горизонтального переполнения.
- Затем выполняются полные `pnpm check`, `pnpm test`, `pnpm build` и production smoke-проверка после развёртывания.

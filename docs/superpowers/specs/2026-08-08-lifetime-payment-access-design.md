# Постоянный доступ в платёжных тарифах

## Цель

Добавить бессрочный доступ после разовой оплаты общего тарифа или персонального предложения через Prodamus и Lava. Доступ не имеет даты окончания, сохраняет приоритет над более поздними временными покупками и может быть отключён только администратором.

## Модель

Платёжное поведение и длительность доступа остаются независимыми понятиями:

- `kind` продолжает определять разовую (`one_time`) или рекуррентную (`recurrent`) оплату;
- `accessType` принимает `limited` или `lifetime`;
- `accessDays` используется только при `accessType = limited` и равен `null` для `lifetime`.

Постоянный доступ допустим только для разовой оплаты. Рекуррентный тариф всегда требует положительное число дней. Это правило проверяется общими схемами, API и формами.

## Хранение данных

В общих тарифах и персональных предложениях сохраняются `access_type` и nullable `access_days`. В платёжном заказе сохраняются снимки обоих значений, чтобы уже начатая оплата не меняла результат после редактирования тарифа.

Существующие строки мигрируются как `access_type = limited`; их текущие сроки остаются без изменений. В таблице подписок бессрочный доступ представлен активной записью с `expires_at = null`, что уже поддерживается моделью членства.

## Обработка оплаты и приоритет

После подтверждения оплаты:

- ограниченный тариф рассчитывает срок по существующему правилу продления;
- постоянный тариф создаёт активную подписку с `expires_at = null`;
- если у клиента уже есть активный бессрочный доступ, последующая временная покупка не лишает его доступа;
- выбор текущего членства всегда предпочитает активную бессрочную запись временным записям независимо от времени их создания;
- отключение администратором продолжает использовать существующий механизм изменения статуса доступа.

Напоминания об окончании и сегмент «скоро истекает» игнорируют записи без даты окончания.

## Интерфейс

Формы общего тарифа и персонального предложения получают выбор «Ограниченный срок / Постоянный доступ». При постоянном доступе поле дней скрыто. Рекуррентный тип автоматически использует ограниченный срок.

Карточки тарифов, персональная платёжная страница, история персональных ссылок и профиль клиента показывают «Постоянный доступ» или «Без ограничения срока» вместо количества дней и даты окончания.

## Совместимость провайдеров

Для Prodamus и Lava постоянный тариф отправляется как обычная разовая покупка. Внешний каталог Lava по-прежнему определяет платёжный тип и цену; внутренний `accessType` определяет только результат успешной оплаты.

## Ошибки и валидация

API отклоняет:

- `lifetime` вместе с `recurrent`;
- `limited` без положительного `accessDays`;
- `lifetime` с непустым `accessDays`.

Webhook остаётся идемпотентным. Повторное уведомление не создаёт второй доступ.

## Проверка

Автоматические тесты покрывают схемы общего тарифа и персонального предложения, снимки заказа, выдачу бессрочного доступа обоими обработчиками оплаты, приоритет бессрочной подписки, формы и пользовательские подписи. Затем выполняются тесты затронутых пакетов, проверка типов и сборка.

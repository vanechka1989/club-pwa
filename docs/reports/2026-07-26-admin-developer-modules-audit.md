Дата: 2026-07-26  
Production: https://club2.myn8nservertest.ru  
Версия production: `5167452`, service worker `club-pwa-v234`

## Итог

Основные административные и developer-сценарии работоспособны. Разработчик видит полный набор из восьми панелей, администратор с полными разрешениями — семь панелей без owner-only сервера. Администратор без разрешений не вызывает закрытые API и остаётся в безопасном пользовательском интерфейсе.

Полный цикл модулей пройден в изолированном контуре: создание и редактирование модуля, выбор вертикальных/горизонтальных карточек, создание урока, добавление текста, фото, видео YouTube и аудио, редактирование урока, удаление, восстановление, редактирование и удаление модуля.

Обнаружена одна критическая проблема потери данных и две функциональные слабости среднего уровня.

## Найденные проблемы

### Критический: удаление модуля необратимо, хотя интерфейс обещает корзину

Диалог сообщает: «Модуль и все уроки внутри него будут перемещены в удалённые». Фактический API `DELETE /admin/learning/categories/:id` сразу:

1. удаляет объекты дополнительных материалов;
2. удаляет основной медиафайл и обложку каждого урока из S3;
3. удаляет категорию и связанные уроки из базы данных.

Восстановление после этого невозможно. Механизм хранения 7 дней существует только для удаления отдельного урока.

Рекомендация P0: запретить физическое удаление модуля из обычного UI. Архивировать категорию и уроки на 7 дней, добавить восстановление модуля и удалять S3 только после окончания TTL. До реализации минимум изменить предупреждение на честное необратимое действие и требовать ввод названия модуля для подтверждения.

### Средний: новый контент публикуется немедленно

Форма не предлагает состояние «Черновик». Создание и изменение урока отправляет `isPublished: true`; интерфейс не использует уже существующие API смены статуса модуля и урока. Ошибка или незаконченный материал может сразу стать виден клиентам.

Рекомендация P1: создавать модуль и урок как черновик, добавить «Предпросмотр», «Опубликовать» и «Снять с публикации», показывать статус на карточке.

### Средний: обычный администратор может получить developer-режим интерфейса из localStorage

`club-preview-mode` по умолчанию равен `developer`, а видимость списка релизов проверяется только по этому значению. При свежем localStorage администратор способен открыть статический developer-only экран релизов. Серверные owner-only операции при этом остаются закрыты благодаря `realRole`, поэтому прямой утечки серверных полномочий не обнаружено.

Рекомендация P1: разрешать developer UI только при `realRole === "owner"`; при загрузке нормализовать сохранённый preview mode под фактическую роль пользователя.

### Низкий: слишком крупные компоненты

- `AdminSection.vue`: 5 131 строка / около 223 KB исходного кода.
- `LearningSection.vue`: 3 772 строки / около 148 KB.

Ленивая загрузка защищает первоначальную загрузку приложения, но размер компонентов повышает риск регрессий при изменениях.

Рекомендация P2: продолжить выделение панелей и редактора уроков в самостоятельные компоненты/composables с отдельными контрактными тестами.
